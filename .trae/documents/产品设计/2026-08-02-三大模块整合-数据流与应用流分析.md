# 三大模块深度整合 · 数据流 & 应用流分析

> **版本**: v0.1
> **日期**: 2026-08-02
> **目的**: 在动手整合「数据发现 / 数据管理 / 数据探索」三个模块前，先把数据流 + 应用流摸透，识别整合点 & 风险。
> **范围**: 仅前端展示,所有数据来源为 mock(见 `/Users/mac/nis_mock/data_comunity/data_comunity/src/mock`)

---

## 0 · TL;DR

三模块现状:
- **数据发现 (discovery)** — 消费端。资产/数据地图/血缘/指标地图/客户 360。**17+ 页面**。
- **数据管理 (management)** — 管控端。元数据/标准/服务/资产上下架/权限。**40+ 页面**。
- **数据探索 (exploration)** — 操作端。客群中心(标签/事件/人群)/分析流程/外数评估/指标看板。**30+ 页面**。

它们目前是**平行的三个一级菜单**,数据流割裂、菜单割裂、Mock 数据多源,关联隐藏在路由 path 而非数据结构里。

**整合的核心瓶颈不是"页面合并",而是"共享数据底座 + 跨域跳转契约 + 统一身份"**。

## 3 · 整合点识别(按优先级)

### 🔴 P0 · 整合必须做

1. **统一 Mock 数据底座(避免三套并行 ts/js)**
   - 现状:`data-map`、`metrics`、`crowd`、`touch`、`external-data-v1` 都是 ts/js 双份并存,意味着修改一处要改两处。
   - 动作:收敛到 TS 一份,统一从 `src/mock/shared/*` 的 Store 取数,模块级 MockMethod 只做"对外 HTTP 接口包装"。

2. **跨模块跳转契约化(消灭硬编码 path)**
   - 现状:exploration/index.vue 直接 `router.push('/discovery/index')` 等。
   - 动作:抽 `src/composables/useCrossNav.ts` 或路由常量表 `ROUTE_PATHS` + `crossNav.to('discovery', 'data-map')`。

3. **共享 MetadataStore / BusinessConceptStore 真正接入三模块**
   - 现状:Store 已存在,但 `data-map.ts` / `metric-management` / `tag-system` 都自管数据。
   - 动作:
     - discovery/data-map → `MetadataStore.getTables()`(替换本地 mock)
     - management/asset-management → 写 `MetadataStore`(注册/上下架要回写)
     - exploration/search → 复用 `search-api`(已存在)

### 🟡 P1 · 整合应该做

4. **客户 360 v3.3 字段权限 → 接入 management 的 permission 中心**
   - PRD 提到的 PD-COM 权限中心,前端对应 `management/permission/*`。
   - 动作:`discovery/customer360` 自定义查询抽屉从 `usePermissionStore()` 读 `visible/copyable/searchable`,而非本地 mock 写死。

5. **指标统一 Schema**
   - discovery/metrics、management/metric-management、exploration/indicator-dashboard 三处 schema 不同。
   - 动作:定义 `Metric` 统一接口,各模块做适配器。

6. **外数统一**
   - exploration/external-data-evaluation + risk/external-data-lifecycle + management/service + discovery/data-resources/external。
   - 动作:统一 `ExternalDataAsset` 模型,统一列表/详情页组件。

### 🟢 P2 · 锦上添花

7. **客户 / 人群打通**:exploration/audience 与 discovery/customer360 共享 userId 体系。
8. **统一工作台首页**:exploration 的工作台范式复制到 discovery、management 入口(目前两者都是占位)。
9. **跨模块搜索**:在 exploration 顶部已有 `a-input-search`,接入 `search-api`,结果按模块分组跳。

## 5 · 风险与建议

### 5.1 风险
- **R1 路由名冲突**:三模块共享 `/discovery`、`/management`、`/exploration`,整合后必须保证 `name` 唯一(目前已经有重复检测告警 `Duplicate route name detected`)。
- **R2 ts/js 重复 mock**:`data-map.ts` 与 `data-map.js` 谁是真源不明,需先 grep 引用关系。
- **R3 共享 Store 改造范围大**:`MetadataStore` 接入会触动 discovery 的 data-map / metrics-map / variable-map / feature-map,改动面广。
- **R4 菜单层级**:TOP_MENU_ORDER 是硬编码顺序,新增"工作台"会打乱现有导航结构。
- **R5 跨应用跳转**:`/dmt` `/touch` `/risk` 通过 `window.location.href` 跨子应用,不能用 `router.push`,整合工作台跳转要识别主/子边界。

### 5.2 建议落地顺序

| 阶段 | 内容 | 影响 |
|:---|:---|:---|
| ① 摸底 & 立项 | 本文档 + 三个模块页面清单 + Mock 依赖矩阵 | 0 |
| ② 数据底座 | 共享 Store 接入 + 消灭 ts/js 重复 | 大 |
| ③ 跨模块跳转契约 | `useCrossNav` + 路由常量 | 中 |
| ④ 工作台统一 | 替换 discovery/management 入口占位为统一工作台 | 中 |
| ⑤ 客户 360 v3.3 | 字段权限走 management/permission,自定义查询接入 shared search-api | 中(独立 PRD) |
| ⑥ 指标/外数统一 | Metric / ExternalData schema 统一 + 跨模块复用 | 大 |
