# 项目精简架构图

生成时间：2026-06-24

## 1. 一句话概览

当前项目是一个以 `apps/*` 为主要业务承载、以 `packages/*` 为共享层、以 `mock` 为主要数据来源的前端展示型 monorepo；根目录 `src/` 中存在较多历史实现，后续应逐步迁移并退役。

## 6. 当前最关键的结构特征

- 根 `src/` 中存在较多历史实现，建议把它视为过渡层，仅用于短期保障可运行与路由兼容。
- 目标是由 `apps/main-shell` 取代根 `src/` 的“主应用壳”角色，所有业务能力以 `apps/*` 为主承载。
- 项目已具备业务域拆分形态，但同一业务仍存在根应用与子应用并存现象，需要做边界收口与迁移归位。
- 共享层已经出现，但复用体系尚未彻底包化。
- `mock` 是系统稳定运行的核心支撑，但来源分散、链路多样。
- 当前更像“架构迁移中的混合态”，而不是已经完全成型的微前端平台。

## 7. 推荐阅读顺序

建议按以下顺序理解项目：

1. 先看根入口与脚本：`package.json`
2. 再看子应用：`apps/risk-app`、`apps/touch`、`apps/mkt-app`、`apps/dex-app`
3. 再看共享层：`packages/shared-api`
4. 再看数据来源：`src/mock`
5. 最后再回看根 `src/`：用于理解历史兼容与迁移成本（建议逐步退役）

## 8. 结论

如果把这个仓库抽象成一句图景，可以理解为：

> 一个以主应用为壳、以多个业务子应用为扩展单元、以共享包为基础设施、以 mock 数据为运行底座的前端展示平台。
